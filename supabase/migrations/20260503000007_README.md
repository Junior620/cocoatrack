# Migration RLS pour les Tables Satellite

## Vue d'ensemble

Cette migration crée les politiques Row Level Security (RLS) pour toutes les tables satellite :
- `satellite_imagery`
- `ndvi_results`
- `deforestation_events`
- `yield_predictions`
- `satellite_cache_metadata`
- `satellite_audit_logs`

## Fichiers

1. **20260503000007_satellite_rls_policies.sql** - Migration principale avec toutes les politiques RLS
2. **20260503000007_test_satellite_rls.sql** - Script de vérification (optionnel)

## Modèle de contrôle d'accès

### Règles générales

Toutes les données satellite sont liées aux parcelles. L'accès suit le modèle :
- **Via planteur** : `planteur.cooperative_id`
- **Via import** : `import_file.cooperative_id`

### Permissions par rôle

| Rôle | SELECT | INSERT | UPDATE | DELETE |
|------|--------|--------|--------|--------|
| **Viewer** | ✓ (sa coopérative) | ✗ | ✗ | ✗ |
| **Agent** | ✓ (sa coopérative) | ✓ | ✓ | ✗ |
| **Manager** | ✓ (sa coopérative) | ✓ | ✓* | ✗ |
| **Admin** | ✓ (toutes) | ✓ | ✓ | ✓ |

\* Les managers peuvent mettre à jour les `deforestation_events` (acknowledge/dispute)

### Cas spéciaux

#### deforestation_events
- **UPDATE** nécessite `is_manager_or_above()` pour gérer les alertes EUDR
- Permet aux managers d'approuver ou contester les événements de déforestation

#### satellite_audit_logs
- Les utilisateurs voient leurs propres logs
- Les managers voient tous les logs de leur coopérative
- **Pas de UPDATE** (logs immuables)

#### satellite_cache_metadata
- Gestion automatique du cache
- Les fonctions système utilisent `SECURITY DEFINER` pour contourner RLS si nécessaire

## Tests recommandés

### Test 1 : Vérification de base
```sql
-- Vérifier que RLS est activé
SELECT tablename, rowsecurity 
FROM pg_tables 
WHERE schemaname = 'public' 
  AND tablename LIKE 'satellite%'
  OR tablename IN ('ndvi_results', 'deforestation_events', 'yield_predictions');
```

### Test 2 : Compter les politiques
```sql
-- Devrait retourner 23+ politiques
SELECT COUNT(*) as total_policies
FROM pg_policies 
WHERE schemaname = 'public'
  AND tablename IN (
    'satellite_imagery',
    'ndvi_results',
    'deforestation_events',
    'yield_predictions',
    'satellite_cache_metadata',
    'satellite_audit_logs'
  );
```

### Test 3 : Vérifier les politiques par table
```sql
SELECT tablename, COUNT(*) as policy_count
FROM pg_policies 
WHERE schemaname = 'public'
  AND tablename IN (
    'satellite_imagery',
    'ndvi_results',
    'deforestation_events',
    'yield_predictions',
    'satellite_cache_metadata',
    'satellite_audit_logs'
  )
GROUP BY tablename
ORDER BY tablename;
```

## Rollback (si nécessaire)

Si vous devez annuler cette migration :

```sql
-- Désactiver RLS
ALTER TABLE public.satellite_imagery DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.ndvi_results DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.deforestation_events DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.yield_predictions DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.satellite_cache_metadata DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.satellite_audit_logs DISABLE ROW LEVEL SECURITY;

-- Supprimer toutes les politiques
DROP POLICY IF EXISTS satellite_imagery_select ON public.satellite_imagery;
DROP POLICY IF EXISTS satellite_imagery_insert ON public.satellite_imagery;
DROP POLICY IF EXISTS satellite_imagery_update ON public.satellite_imagery;
DROP POLICY IF EXISTS satellite_imagery_delete ON public.satellite_imagery;

-- Répéter pour chaque table...
```
